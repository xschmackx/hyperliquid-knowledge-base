## Three published objects

1. **HIP-3 / deployer fee share** — extra share a deployer can configure on deployed assets.
2. **Aligned-collateral fee discounts** — published trading-fee multipliers when an aligned quote asset is the spot quote or HIP-3 collateral. AQAv2 does not get those multipliers.
3. **Protocol-vault fee share** — HLP “accrues a portion of trading fees.” That portion is unpublished.

Do not add these into one rate.

## HIP-3 deployer fee share

Official Fees leaf and official HIP-3 leaf, checked 2026-09-27.

Two official share phrasings sit side by side. This page does not collapse them.

1. HIP-3 deployers can configure an additional fee share between **0–300%** (**0–100%** for growth mode). If the share is above **100%**, the protocol fee is also increased to equal the deployer fee.
2. Spot and HIP-3 perp deployers may choose to keep **up to 50%** of trading fees generated by their deployed assets.

Official Fees leaf also publishes a third view as `feeRates`. Quote only; do not invent a reconciliation with (1) or (2).

```typescript
type Args =
  | {
      type: "spot";
      isStablePair: boolean;
    }
  | {
      type: "perp";
      deployerFeeScale: number;
      growthMode: boolean;
    };

function feeRates(
  fees: { makerRate: number; takerRate: number }, // fees from userFees info endpoint
  activeReferralDiscount: number, // number from userFees info endpoint
  isAlignedQuoteToken: boolean,
  args: Args,
) {
  const scaleIfStablePair = args.type === "spot" && args.isStablePair ? 0.2 : 1;
  let scaleIfHip3 = 1;
  let growthModeScale = 1;
  let deployerShare = 0;
  if (args.type === "perp") {
    scaleIfHip3 =
      args.deployerFeeScale < 1
        ? args.deployerFeeScale + 1
        : args.deployerFeeScale * 2;
    deployerShare =
      args.deployerFeeScale < 1
        ? args.deployerFeeScale / (1 + args.deployerFeeScale)
        : 0.5;
    growthModeScale = args.growthMode ? 0.1 : 1;
  }

  let makerPercentage =
    fees.makerRate * 100 * scaleIfStablePair * growthModeScale;
  if (makerPercentage > 0) {
    makerPercentage *= scaleIfHip3 * (1 - activeReferralDiscount);
  } else {
    const makerRebateScaleIfAlignedQuoteToken = isAlignedQuoteToken
      ? (1 - deployerShare) * 1.5 + deployerShare
      : 1;
    makerPercentage *= makerRebateScaleIfAlignedQuoteToken;
  }

  let takerPercentage =
    fees.takerRate *
    100 *
    scaleIfStablePair *
    scaleIfHip3 *
    growthModeScale *
    (1 - activeReferralDiscount);
  if (isAlignedQuoteToken) {
    const takerScaleIfAlignedQuoteToken = isAlignedQuoteToken
      ? (1 - deployerShare) * 0.8 + deployerShare
      : 1;
    takerPercentage *= takerScaleIfAlignedQuoteToken;
  }

  return { makerPercentage, takerPercentage };
}
```

From that formula, as printed:

- If `deployerFeeScale < 1`: `scaleIfHip3 = deployerFeeScale + 1` and `deployerShare = deployerFeeScale / (1 + deployerFeeScale)`.
- If `deployerFeeScale >= 1`: `scaleIfHip3 = deployerFeeScale * 2` and `deployerShare = 0.5`.

Official growth-mode sentence on Fees: deployer fee scale is the amount the deployer keeps as a percentage of the user’s fees **before** applying aligned stablecoin collateral discount, if applicable. Growth-mode bound: scale must be set between **0 and 10**. Setting growth mode has a **30-day** cooldown per asset.

Official recipient hook named on HIP-3 deployer actions: `setFeeRecipient`. How that action is signed is tooling. This page names the type only.

HIP-3 product (stake, listing slots, slashing) stays on [HIP-3 builder-deployed perps](../markets/hip-3-markets.md).

Sources: [Fees](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees.md); [HIP-3: Builder-deployed perpetuals](https://hyperliquid.gitbook.io/hyperliquid-docs/hyperliquid-improvement-proposals-hips/hip-3-builder-deployed-perpetuals.md); [HIP-3 deployer actions](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/hip-3-deployer-actions.md) — checked 2026-09-27.

## Growth mode as fee logic

Official Fees leaf uses both **90%** and **≥90%**. This page does not collapse them. [Trading fees](trading-fees.md) already refused that collapse.

- Intro / growth-mode section: when growth mode is activated for an HIP-3 perp, protocol fees, rebates, volume contributions, and L1 user rate-limit contributions are reduced by **90%**.
- Same leaf: when a deployer activates growth mode, there is a **≥90%** reduction on the all-in fees. Rebates and volume contributions will also be **≥90%** lower.
- Official summary: baseline all-in taker rate under growth mode will be between **0.0045%–0.009%** (5–10x lower than the 0.045% baseline fee for validator-operated perps).
- Growth mode applies on top of other multipliers, including staking discounts.
- Official `feeRates`: `growthModeScale = args.growthMode ? 0.1 : 1`.

Eligibility lists and validator-vote examples stay off this page.

Source: [Fees](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees.md) — checked 2026-09-27.

## Aligned-collateral fee discounts

Official Fees and Aligned quote assets leaves, checked 2026-09-27.

AQAv1 published *trading-fee* benefits when used as the quote asset for a spot pair or the collateral asset for HIP-3 perps:

1. **20%** lower taker fees
2. **50%** better maker rebates on the Fees leaf; **50%** larger maker rebates on the Aligned quote assets leaf
3. **20%** more volume contribution toward fee tiers

Those three lines are AQAv1 only. Official AQAv2: **no** trading-fee or volume-contribution benefit. Do not apply 20/50/20 to v2.

AQAv2 shares are protocol revenue shares, not a user discount:

- Treasury address shares **100%** of the AQA rate with the protocol (official: twice the v1 revenue-share).
- Deployers share **approximately 90%** of cost-adjusted reserve yield revenue on their Hyperliquid supply with the protocol.

v1 also has a protocol share: **50%** of the AQA rate flows to the protocol. That is not the 20/50/20 user discount.

Official Fees: spot pairs between two spot quote assets have **80%** lower taker fees, maker rebates, and user volume contribution. That is a two-quote-asset pair rule, not AQAv1 20/50/20.

Official `feeRates` applies alignment after deployer share:

- `takerScaleIfAlignedQuoteToken = (1 - deployerShare) * 0.8 + deployerShare`
- rebate scale uses `(1 - deployerShare) * 1.5 + deployerShare`

Official HIP-3 leaf: HIP-3 markets incorporate usual trading-fee discounts including staking, referral, and aligned collateral. Official: aligned stablecoin collateral will automatically receive reduced fees once the alignment condition (which is being updated based on user and deployer feedback) is implemented. Whether that condition has shipped, and how it maps onto AQAv1 versus AQAv2, is **unknown here**.

Official permissionless spot quote-asset requirement: **zero deployer fee share on the quote token**. That is a listing prerequisite, not the HIP-3 0–300% knob.

What AQAv1 versus AQAv2 *is* stays on [Aligned quote assets](../markets/aligned-quote-assets.md). This page is the fee-logic grouping.

On this 2026-09-27 re-read of [HIP-3 deployer actions](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/hip-3-deployer-actions.md), the 2026-09-17 comment “no aligned quote assets on mainnet” was **not** on the fetched leaf. Live mainnet inventory of aligned quote assets is **unknown here**.

Sources: [Fees](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees.md); [Aligned quote assets](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/aligned-quote-assets.md); [Permissionless spot quote assets](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/permissionless-spot-quote-assets.md); [HIP-3: Builder-deployed perpetuals](https://hyperliquid.gitbook.io/hyperliquid-docs/hyperliquid-improvement-proposals-hips/hip-3-builder-deployed-perpetuals.md); [HIP-3 deployer actions](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/hip-3-deployer-actions.md) — checked 2026-09-27.

## Protocol-vault fee share

Official Protocol vaults leaf: HLP **accrues a portion of trading fees**. That leaf does not publish the numeric portion. This page leaves it **unknown**.

Official HyperCore vaults (legacy): **protocol vaults do not have any fees or profit share**. Official on that leaf: vault owners of user vaults receive **10% of total profits**.

Both sentences are official. They are not one rate. The 10% figure is user-vault leader profit share, not an HLP trading-fee split.

Official Fees destination sentence: fees are entirely directed to the community (**HLP**, the **assistance fund**, and **deployers**). Assistance fund address `0xfefefefefefefefefefefefefefefefefefefefe` converts trading fees to HYPE as L1 execution; that HYPE is burned. Those are destination facts. They are not a published HLP split.

HLP as a liquidity product (4-day lock, community-owned, liquidations) stays on [Protocol vaults](../markets/protocol-vaults.md).

Sources: [Protocol vaults](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/vaults/protocol-vaults.md); [HyperCore vaults (legacy)](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/vaults/hypercore-vaults-legacy.md); [Fees](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees.md) — checked 2026-09-27.
